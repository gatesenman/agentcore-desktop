# AgentCore 桌面端迭代记录

本文记录基于 `gatesenman/agentcore-desktop` 远端 `main`（`78f02592`）的五轮实质迭代。不包含真实密钥，也不声称已在 Windows 上完成安装包验证。

## 第 1 轮：可运行基线与网关契约测试

### 审计与验收标准

- 仓库 README 未给出可复制的网关安装/测试命令；`agent-service` 没有测试，错误后端会在导入时变成 `KeyError`。
- 验收：
  1. `cd agent-service && pytest -q` 在无 API Key 条件下全部通过。
  2. `/healthz`、`/v1/models`、非流式与流式 `/v1/chat/completions`（mock）行为可断言。
  3. 管理接口拒绝非 JSON；未知后端返回明确中文错误而不是 KeyError。
  4. `GET /admin/backend` 不回显 `api_key` 等密钥字段。
  5. `.env` / `gateway.json` 仍被 gitignore。

### 改动

- 将网关改为 `create_app` / `create_runtime` / `load_config` 工厂，uvicorn 使用惰性 ASGI 包装，测试不必在 import 时加载用户目录下的 `.env`。
- 配置目录不再于 import 时盲目 `mkdir`；仅在保存设置时创建。
- 未知后端名称改为 `ValueError` / HTTP 400，中文说明可选值。
- `/healthz` 增加 `uptime_s`、`last_error`（本轮只记录，详细健康语义在第 3 轮扩展）。
- 新增 `requirements.txt`、`requirements-dev.txt`、`agent-service/README.md` 与 `tests/test_gateway_contract.py`。

## 第 2 轮：应用身份、数据目录、协议隔离与密钥防护

### 审计与验收标准

- 远端已有 `AGENTCORE_DESKTOP_IDENTITY` 默认品牌（`com.agentcore.desktop`），但 Windows AUMID 仍取 `dev.zcode.app`，协议仍注册 `zcode://`，家目录设置仍读 `~/.zcode`，Linux 还写入 `zcode.desktop` / `x-scheme-handler/zcode`。这会继续碰到已安装的 ZCode 数据与协议。
- 兼容性矩阵文件名在仓库中是乱码。
- 验收：
  1. `node --test tests/product-isolation.test.mjs` 全部通过。
  2. 默认 appId / 打包 AUMID 为 `com.agentcore.desktop`，协议为 `agentcore`，家目录数据目录为 `.agentcore-desktop`。
  3. `AGENTCORE_DESKTOP_IDENTITY=0` 可回退 ZCode 路径与 `zcode://`。
  4. 示例文件不含真实密钥；`.env` / `gateway.json` 仍被忽略。
  5. 第 1 轮网关契约测试保持通过。

### 改动

- 修正 `resolveWindowsAppUserModelId*`，打包态与 electron-builder `appId` 对齐。
- 新增 `resolveDesktopProtocolScheme` / `resolveProductHomeDataDirName`，用于安装包协议、深度链接解析、Finder 服务、Linux `.desktop` 与 mime 类型。
- `getZCodeDataRootDir`、设置文件引导路径、存储根解析改为默认 `~/.agentcore-desktop`。
- 将乱码文档重命名为 `docs/兼容性矩阵.md`。
- 增加 `agent-service/.env.example`（只有注释，无密钥）。
- 同步更新相关单元测试中的协议与路径断言（本轮未安装 ZCode 完整 monorepo，故未跑 vitest 全量）。

### 已知限制

- 未在真实 Windows 上验证 AUMID 与协议注册；验收基于源码契约与单元测试。
